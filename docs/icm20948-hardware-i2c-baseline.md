# ICM-20948 硬件 I²C 已验证基线

适用于当前 STM32F103 FreeRTOS 模板中的 ICM-20948 姿态传感器调试。此文档记录本次实际下载验证通过的基线；迁移或重构时先保留该基线，再逐项修改。

## 硬件和总线

- 使用 STM32F103 **I2C2 硬件外设**，不是软件模拟 I²C。
- PB10 接 SCL，PB11 接 SDA；两脚配置为复用开漏，I²C 标准模式 100 kHz。板上已有上拉。
- ICM-20948 的 7 位地址为 `0x68`。通过 STM32 标准库发送地址时左移一位：写 `0xD0`，读 `0xD1`。
- USART1 用于调试打印，115200、8N1。

## 初始化和读取

1. 初始化前读取总线线路状态。若 MCU 重启后传感器仍把 SDA 拉低，先用开漏 GPIO 释放总线，最多给 SCL 补 9 个脉冲，再发 STOP；只有 SCL、SDA 均为高才初始化 I2C2。
2. 读取 Bank 0 的 `WHO_AM_I` 寄存器 `0x00`，应得到 `0xEA`。这一步同时确认地址、寄存器访问和基本 I²C 链路。
3. 写 Bank 0 的 `PWR_MGMT_1 (0x06)=0x01`、`PWR_MGMT_2 (0x07)=0x00` 唤醒器件；随后按驱动设置 Bank 2 的陀螺仪/加速度计量程和采样分频，最后切回 Bank 0。
4. 加速度数据从 `0x2D` 开始，陀螺仪数据从 `0x33` 开始；每轴为高字节在前的有符号 16 位二补数。当前 ±2g 配置按 16384 LSB/g 换算。静态 Roll/Pitch 由加速度估算，不能据此得到绝对航向角（Yaw）。

## STM32F1 两字节接收时序

每次两字节读取都要按 N=2 特例处理，不能把 ACK/STOP 放到随意的位置：

1. 开始接收地址阶段前设置 `POS=Next`、`ACK=1`。
2. 接收地址被确认并清除 ADDR 后，立即关闭 ACK。
3. 等待 `BTF=1`，请求 STOP，紧接着连续读取两次数据寄存器 DR。
4. 恢复 `ACK=1`、`POS=Current`，并等待 BUSY 清零后才开始下一事务。

事务的每个等待阶段都应有限时；日志至少保留当前错误阶段和 BUSY/SCL/SDA 状态，避免无响应时死锁或只得到模糊的失败信息。单字节和大于两字节的接收序列与 N=2 不同，修改时应分别按 STM32F1 RM0008 处理。

## 本次实测结果

串口确认：

```text
I2C2 RECOVERY=0 BUSY=0 SCL=1 SDA=1 ERR=0
ICM init OK: WHO_AM_I=0xEA, addr=0x68
ACC raw X=... Y=... Z=... | GYRO raw X=... Y=... Z=... | Roll=... | Pitch=...
```

用户观察到多行连续的加速度、陀螺仪和角度数据，未再出现 I²C 错误。一次静置观测约 Roll 39.3–40.4°、Pitch -0.2 至 -1.4°；具体角度由安装姿态决定，不能当作校准后的机械零位。

## 本次定位的两个故障

### 故障 1：初始化前 I²C 总线一直 BUSY

**现象：** 串口输出 `I2C2 BUSY=1 SCL=1 SDA=0 ERR=0`，随后 `ICM init failed: code=11, WHO_AM_I=0x00`。

**定位：** `code=11` 是 Bank Select 写操作返回 `10 + 1`；其中阶段码 `1` 表示还没发 START，就在等待 `I2C_FLAG_BUSY` 清零时超时。此时 WHO_AM_I 尚未成功读取，不能把 `0x00` 当作传感器返回值。MCU 复位后，若传感器仍保持上一次未完成的 I²C 事务，SDA 可能继续被从机拉低。

**解决：** 初始化 I2C2 前先禁用/复位外设，将 PB10/PB11 临时配置为开漏 GPIO 并释放总线；若 SDA 仍低，最多补 9 个 SCL 时钟，再生成 STOP。确认两根线都为高后才切回复用开漏并初始化硬件 I2C2。之后串口验证为 `RECOVERY=0 BUSY=0 SCL=1 SDA=1 ERR=0`，`WHO_AM_I=0xEA`。

### 故障 2：传感器初始化成功，但读取加速度时 BUSY 等待超时

**现象：** 已输出 `ICM init OK: WHO_AM_I=0xEA, addr=0x68`，紧接着读取原始数据时报 `I2C read failed: code=1`。读取函数的 `code=1` 是事务开始前等待 BUSY 清零超时，因此数据尚未进入 ACK/寄存器/字节转换阶段。

**定位与修正：** 原两字节接收逻辑没有设置 STM32F1 两字节接收所需的 `POS=Next`，且把关闭 ACK 放在等待 BTF 之后；此外 STOP 后没有等待 BUSY 清零再开始下一笔事务。修正为：接收前设置 `POS=Next` 并开启 ACK；接收地址阶段清除 ADDR 后立即关闭 ACK；等待 BTF，发 STOP 并连续读两次 DR；恢复 ACK/POS，并等待 BUSY 清零。写事务和单字节读事务也在 STOP 后等待 BUSY 清零，避免下一笔事务过早启动。错误日志同时打印 BUSY/SCL/SDA/ERR，便于区分总线未释放与传输阶段错误。

**验证：** 修正后用户实测到 I²C 初始化成功，并连续输出加速度、陀螺仪原始值和 Roll/Pitch，没有再出现 `code=1`。时序依据为 STM32F1 RM0008 的 N=2 master receiver 流程。

## 迁移到 FreeRTOS 的保护规则

- 先原样保留本次已验证的 I²C 初始化、总线恢复、事务函数与传感器寄存器配置。
- 迁移时优先只把已验证的读取调用放进传感器任务；不要同时重写 I²C 时序、改变引脚/地址和调整任务调度。
- 每次变更后先检查启动诊断与 `WHO_AM_I=0xEA`，再确认原始数据连续更新、无 BUSY 卡死；之后再进入滤波、标定或姿态解算。
