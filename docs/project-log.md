# 项目开发过程记录

**项目名称：** 基于 STM32F103 与 FreeRTOS 的双轮自平衡车控制系统

这里记录项目实际推进过程中的方案、选择依据与验收结果。以下只写已经确认的项目背景和当前工程状态；后续进展在新的阶段记录中补充，不把计划写成已经完成的功能。

## 2026-10-19：准备 F103 FreeRTOS 工程模板

### 当前背景

项目准备以已有双轮自平衡车为基础，将工程逐步迁移到 FreeRTOS。用户确认新工程使用 F103，且现有平衡车硬件作为后续迁移基础。本阶段先搭建独立模板，避免直接修改原工程，也便于先学习任务创建和调度器的运行方式。

### 本阶段目标

建立一份针对 STM32F103RC 的 FreeRTOS 工程，并用两个简单周期任务验证工程配置和内核代码能够通过编译。本阶段不迁移平衡车控制，不连接或驱动电机。

### 方案与选择依据

- 使用 STM32F103RC 工程配置，而不是此前的 STM32F407 FreeRTOS 模板，避免目标芯片、内核移植层与启动配置不匹配。
- 使用本机 Keil ARM Compiler 6.22 和 FreeRTOS Kernel V11.3.1 的 GCC ARM_CM3 移植层；F103 使用 Cortex-M3。
- 使用 `heap_4.c` 提供 FreeRTOS 动态内存。
- 在 `main.c` 中保留两个简短示例任务：TaskA 每 500 ms 更新一次 `TaskA_Count`，TaskB 每 1000 ms 更新一次 `TaskB_Count`。暂时不拆出独立任务文件，先让任务函数、任务创建和调度器启动的关系清晰可见。
- 原平衡车工程保持不变。新模板是单独工程，后续是否迁移哪些模块，由实际学习和验证结果决定。

### 当前工程逻辑

`复位启动 → SystemInit 配置系统时钟 → main 创建 TaskA 和 TaskB → 启动 FreeRTOS 调度器 → 两个任务分别延时并更新计数器`

两个计数变量可加入 Keil Watch 窗口，用于观察任务是否运行。这里的周期是示例任务的延时周期，不是平衡车控制周期。

### 工程与硬件基础

- **目标芯片：** STM32F103RC（Cortex-M3）。
- **开发环境：** Keil MDK，ARM Compiler 6.22；STM32F1xx DFP 2.4.1。
- **FreeRTOS：** Kernel V11.3.1，GCC ARM_CM3 移植层，`heap_4`。
- **既有平衡车代码：** 参考工程中包含 ICM20948、编码器、电机驱动和 OLED 等代码；这些模块尚未接入本模板。本阶段未重新核验实物接线。

## 2026-10-19：验证 ICM-20948 硬件 I²C 读取

### 实际问题与定位

初次传感器初始化失败时串口报告 `I2C2 BUSY=1 SCL=1 SDA=0 ERR=0`，`ICM init failed: code=11, WHO_AM_I=0x00`。此时尚未成功读到 WHO_AM_I；错误码 11 是 bank-select 写操作在 START 前等待 BUSY 清零超时，不是芯片返回了 `0x00`。只复位 MCU 后，传感器可能仍保持上一次未完成事务的状态，因此初始化前增加 I²C GPIO 开漏恢复：释放总线、必要时最多补 9 个 SCL 脉冲，再生成 STOP，并确认 SCL/SDA 都为高。

第二个故障发生在 `ICM init OK: WHO_AM_I=0xEA` 之后：读取加速度立即报告 `code=1`。该码对应读函数开始前等待 BUSY 清零超时，数据还没有进入接收和解析阶段。检查 STM32F1 两字节接收时序后，修正为设置 `POS=Next`，在 EV6 清除 ADDR 后立即关闭 ACK，等待 BTF 后发 STOP 并读两次 DR；同时在写事务、单字节读和两字节读的 STOP 后等待 BUSY 清零。修正后用户实测连续收到加速度/陀螺仪原始值与角度，未再报错。两个故障的现象、码值含义和修复细节见 [`icm20948-hardware-i2c-baseline.md`](icm20948-hardware-i2c-baseline.md)。

### 已验证连接与传输方式

- ICM-20948 通过 STM32F103 的 **I2C2 硬件外设**连接：PB10=SCL、PB11=SDA，I²C 标准模式 100 kHz，GPIO 为复用开漏；板上已有上拉。
- 器件 7 位地址为 `0x68`；标准库传地址时左移一位，写地址字节为 `0xD0`、读地址字节为 `0xD1`。
- 先读 Bank 0 的 `WHO_AM_I (0x00)`，期望值 `0xEA`。初始化后配置 Bank 0 唤醒 (`PWR_MGMT_1=0x01`, `PWR_MGMT_2=0x00`)，再按当前驱动配置 Bank 2 的量程和采样率，最后切回 Bank 0 读传感器输出。
- 当前已验证 1 字节寄存器读取及 2 字节连续读取；2 字节接收遵循 STM32F1 RM0008 的 N=2 专用序列：在接收地址阶段前设置 `POS=Next`、`ACK=1`；EV6 清除 ADDR 后立即关闭 ACK；等 BTF 后请求 STOP 并连续读取两次 DR；恢复 ACK/POS，并等待 BUSY 清零再开始下一笔事务。
- 所有 I²C 等待都有超时。错误日志带 `BUSY/SCL/SDA/ERR`，初始化日志带 `RECOVERY`，便于把总线卡住与器件 NACK、传输阶段超时区分开。

### 板上验收结果

用户下载本次固件后，串口实际输出 `RECOVERY=0 BUSY=0 SCL=1 SDA=1 ERR=0`、`WHO_AM_I=0xEA`，并连续读出加速度与陀螺仪原始值及 Roll/Pitch，没有再出现 I²C 读取错误。一次静置观测中，Roll 约 39.3–40.4°、Pitch 约 -0.2 至 -1.4°；角度是否为机械零位取决于传感器安装姿态，尚未做安装方向校准或零偏标定。

### 后续修改约束

- 这份主循环测试是已验证基线。后续迁入 FreeRTOS 时先保持引脚、地址、初始化顺序、寄存器读取顺序和 2 字节 ACK/POS/STOP 时序不变；一次只改任务封装或调度相关内容，并用同样的 WHO_AM_I 与连续原始数据串口输出回归验证。
- 若以后调整接收字节数，不能把 N=2 时序直接套到 N=1 或 N>2；按 STM32F1 参考手册分别处理。
